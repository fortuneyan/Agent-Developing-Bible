## 1.2 多供应商管理策略

### 1.2.1 从问题出发：为什么需要设计模式？

#### 💡 一个真实的故事

> **程序⚪碎碎念**：我司有个祖传代码,2万行if-else,产品经理说"加个新功能很简单"——我看了3天没看懂逻辑,测试了2周没测完。现在看到"供应商适配"四个字,我的PTSD就犯了。所以这一章我们用设计模式,把if-else炸掉重构：））

#### 问题场景：多供应商的困境

假设你的Agent已经上线,最初只用OpenAI。某天,老板说：

> "我们要支持国产模型,用户可以选择用文心一言还是GPT。"

**方案一：直接写if-else（❌ 错误示范）**

```python
def call_llm(provider, prompt):
    """直接根据供应商调用不同的API"""
    
    if provider == "openai":
        import openai
        response = openai.ChatCompletion.create(
            model="gpt-3.5-turbo",
            messages=[{"role": "user", "content": prompt}]
        )
        return response.choices[0].message.content
    
    elif provider == "wenxin":
        import wenxin
        # 文心一言的接口完全不同
        response = wenxin.call(
            model="ERNIE-Bot",
            prompt=prompt  # 注意：它用的是prompt参数
        )
        return response.result
    
    elif provider == "claude":
        import anthropic
        # Claude的接口又不一样
        response = anthropic.Client().messages.create(
            model="claude-3",
            messages=[{"role": "user", "content": prompt}],
            max_tokens=1024
        )
        return response.content[0].text
    
    else:
        raise ValueError(f"Unknown provider: {provider}")
```

**看起来没什么问题,对吧？**

但当我们继续开发,问题就开始暴露了。

### 🎯 设计模式登场：适配器模式

#### 核心思想：统一接口,隔离变化

**类比理解**：

想象你有一个万能充电器：
- 它有一个标准的USB接口
- 不管你是iPhone、Android还是华为,只要插上就能充电
- 你不需要关心手机的充电协议是什么
- 充电器内部会自动转换

**适配器模式就是这样的"万能充电器"**：
- 定义一个统一的接口
- 为每个供应商实现一个"适配器"
- 业务代码只依赖统一接口
- 添加新供应商只需新增适配器

---

#### 代码演进：从简单到复杂

**第一步：定义统一接口**

```python
from abc import ABC, abstractmethod

# 就像定义"所有充电器必须有USB接口"
class BaseLLMClient(ABC):
    """LLM客户端的统一接口"""
    
    @abstractmethod
    def chat(self, prompt: str) -> str:
        """
        发送对话,返回文本
        
        :param prompt: 用户输入
        :return: 模型回复
        """
        pass
    
    @abstractmethod
    def chat_with_history(
        self, 
        messages: list
    ) -> str:
        """
        发送带历史记录的对话
        
        :param messages: 消息列表
        :return: 模型回复
        """
        pass
```

**关键点**：
- 使用`ABC`（抽象基类）定义接口
- 所有供应商必须实现这两个方法
- 业务代码只依赖这个接口

### 🎯 进阶：工厂模式

#### 新问题：谁来创建适配器？

现在业务代码清爽了,但谁来决定用哪个适配器？

```python
# ❌ 又出现了if-else
def get_llm_client(provider: str) -> BaseLLMClient:
    if provider == "openai":
        return OpenAIAdapter(api_key=os.getenv("OPENAI_KEY"))
    elif provider == "wenxin":
        return WenxinAdapter(access_token=os.getenv("WENXIN_TOKEN"))
    elif provider == "claude":
        return ClaudeAdapter(api_key=os.getenv("CLAUDE_KEY"))
    else:
        raise ValueError(f"Unknown provider: {provider}")

# 使用
client = get_llm_client("openai")
result = client.chat("你好")
```

**问题**：
- 创建对象的逻辑散落在各处
- 每次新增供应商,都要修改这个函数
- 违反了单一职责原则

---

#### 解决方案：工厂模式

**核心思想**：把创建对象的逻辑封装起来

**类比理解**：
- 工厂就像一个自动售货机
- 你按下按钮（指定类型）
- 工厂给你对应的产品（创建对象）
- 你不需要知道产品是怎么制造的

---

**简单工厂实现**：

```python
class LLMClientFactory:
    """LLM客户端工厂"""
    
    @staticmethod
    def create(provider: str) -> BaseLLMClient:
        """
        根据供应商名称创建对应的客户端
        
        :param provider: 供应商名称
        :return: LLM客户端实例
        """
        
        # 从环境变量读取密钥
        if provider == "openai":
            api_key = os.getenv("OPENAI_KEY")
            if not api_key:
                raise ValueError("OPENAI_KEY not set")
            return OpenAIAdapter(api_key=api_key)
        
        elif provider == "wenxin":
            access_token = os.getenv("WENXIN_TOKEN")
            if not access_token:
                raise ValueError("WENXIN_TOKEN not set")
            return WenxinAdapter(access_token=access_token)
        
        elif provider == "claude":
            api_key = os.getenv("CLAUDE_KEY")
            if not api_key:
                raise ValueError("CLAUDE_KEY not set")
            return ClaudeAdapter(api_key=api_key)
        
        else:
            raise ValueError(f"Unknown provider: {provider}")


# 使用
client = LLMClientFactory.create("openai")
result = client.chat("你好")
```

**关键点**：
- 封装了创建对象的逻辑
- 统一处理密钥读取和验证
- 业务代码不需要知道创建细节

**更进一步：配置驱动**

把映射关系放到配置文件,实现真正的解耦：

```yaml
# config/llm_providers.yaml
providers:
  openai:
    adapter_class: llm.adapters.openai_adapter.OpenAIAdapter
    env_key: OPENAI_KEY
    model: gpt-3.5-turbo
    
  wenxin:
    adapter_class: llm.adapters.wenxin_adapter.WenxinAdapter
    env_key: WENXIN_TOKEN
    model: ERNIE-Bot
    
  claude:
    adapter_class: llm.adapters.claude_adapter.ClaudeAdapter
    env_key: CLAUDE_KEY
    model: claude-3
```

```python
# 工厂实现
import yaml
import importlib

class LLMClientFactory:
    """配置驱动的工厂"""
    
    _registry = {}  # 供应商注册表
    
    @classmethod
    def load_config(cls, config_path: str = "config/llm_providers.yaml"):
        """从配置文件加载供应商映射"""
        with open(config_path, encoding='utf-8') as f:
            config = yaml.safe_load(f)
        
        for provider_name, provider_config in config["providers"].items():
            # 解析类路径：llm.adapters.openai_adapter.OpenAIAdapter
            module_path, class_name = provider_config["adapter_class"].rsplit(".", 1)
            
            # 动态导入模块
            module = importlib.import_module(module_path)
            
            # 获取类
            adapter_class = getattr(module, class_name)
            
            # 注册到映射表
            cls._registry[provider_name] = {
                "class": adapter_class,
                "env_key": provider_config["env_key"],
                "model": provider_config["model"]
            }
    
    @classmethod
    def create(cls, provider: str) -> BaseLLMClient:
        """动态创建客户端"""
        if provider not in cls._registry:
            raise ValueError(f"Unknown provider: {provider}")
        
        provider_config = cls._registry[provider]
        adapter_class = provider_config["class"]
        env_key = provider_config["env_key"]
        
        # 读取密钥
        api_key = os.getenv(env_key)
        if not api_key:
            raise ValueError(f"{env_key} not set")
        
        # 创建实例
        return adapter_class(api_key=api_key)


# 初始化工厂（只需一次）
LLMClientFactory.load_config()

# 使用
client = LLMClientFactory.create("openai")
result = client.chat("你好")
```

**关键点**：
- 供应商配置与代码完全分离
- 添加新供应商：只需修改配置文件
- 支持热加载（运行时更新配置）
- 更符合开闭原则

### 📚 设计模式总结

#### 适配器模式

**定义**：将一个类的接口转换成客户希望的另一个接口。

**解决的问题**：接口不兼容

**核心思想**：
- 定义统一接口
- 为不同实现编写适配器
- 客户端只依赖统一接口

**何时使用**：
- 需要对接多个第三方系统
- 第三方接口各不相同
- 希望统一访问方式

**结构图**：
```
客户端 → 统一接口 ← 适配器A → 第三方系统A
                  ← 适配器B → 第三方系统B
                  ← 适配器C → 第三方系统C
```

---

#### 工厂模式

**定义**：定义一个用于创建对象的接口,让子类决定实例化哪一个类。

**解决的问题**：创建对象逻辑复杂

**核心思想**：
- 封装创建过程
- 客户端无需知道具体类
- 集中管理创建逻辑

**何时使用**：
- 创建对象的逻辑复杂
- 需要根据配置动态创建
- 希望集中管理对象创建

**结构图**：
```
客户端 → 工厂 → 根据配置创建 → 产品A
                       ↓        → 产品B
                       ↓        → 产品C
```

---

#### 组合使用的威力

- **适配器**：解决"怎么调用"
- **工厂**：解决"谁来创建"
- **组合**：构建灵活、可扩展的系统

**设计原则体现**：
- ✅ 开闭原则：对扩展开放,对修改关闭
- ✅ 依赖倒置原则：依赖抽象,不依赖具体
- ✅ 单一职责原则：每个类只做一件事
- ✅ 接口隔离原则：接口最小化

### 🎯 实战建议

#### 什么时候该用设计模式？

**不该用**：
- ❌ 只有一个供应商,且不会增加
- ❌ 项目规模很小,过度设计
- ❌ 团队成员不熟悉设计模式

**应该用**：
- ✅ 需要对接多个第三方系统
- ✅ 项目需要长期维护
- ✅ 团队成员理解设计模式

#### 如何避免过度设计？

**原则**：YAGNI（You Aren't Gonna Need It）

- 先写出最简单的代码
- 发现重复时再抽象
- 发现变化时再解耦

**演进路径**：
```
直接调用 → 提取函数 → 适配器模式 → 工厂模式
（简单）  （消除重复） （隔离变化） （集中管理）
```

不要一开始就上设计模式,而是在代码演进过程中,当需要时再引入。
