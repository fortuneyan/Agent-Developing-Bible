## 1. 用户角色详细定义

### 1.0 并发访问模式 ⭐ 重要更新

根据用户确认，系统需要支持**多教师多学生同时在线使用**，特别是在授课和讲解过程中，**一个老师和多个学生同时在同一个频道中**。

#### 并发级别定义

| 并发级别 | 用户规模 | 典型场景 | 技术要求 |
|---------|---------|---------|---------|
| **L1: 单用户** | 1人 | 个人备课、个人学习 | 无需并发控制 |
| **L2: 小规模并发** | 5-20人 | 小班课授课（1教师+20学生） | WebSocket、实时通信 |
| **L3: 中规模并发** | 50-200人 | 大班课授课（1教师+100学生） | 分布式消息队列、负载均衡 |
| **L4: 大规模并发** | 500-2000人 | 多班级同时上课（5班级×40人） | 微服务架构、缓存策略 |
| **L5: 超大规模并发** | 5000+人 | 全校同时在线（100班级×50人） | CDN、边缘节点、弹性伸缩 |

#### 频道（Channel）机制

**频道定义**：一个授课单元，包含一个老师和多个学生，实时同步授课内容和互动。

**频道生命周期**：
```
创建频道（教师）
  ↓
学生加入频道
  ↓
开始授课（实时同步）
  ↓
课堂互动（提问、答题、讨论）
  ↓
结束授课
  ↓
归档频道（保存学情数据）
```

**频道功能特性**：
| 功能 | 说明 | 技术实现 |
|-----|------|---------|
| 实时课件同步 | 教师翻页，学生端同步翻页 | WebSocket推送到所有客户端 |
| 实时学情同步 | 学生答题，教师端实时看到统计 | 实时聚合计算 |
| 实时互动 | 举手、提问、讨论 | 双向实时通信 |
| 录制回放 | 保存授课过程，支持回放 | 视频录制 + 数据回放 |

#### 并发访问场景矩阵

| 场景 | 并发级别 | 频道数量 | 实时性要求 | 技术方案 |
|-----|---------|---------|-----------|---------|
| 个人备课 | L1 | 0 | 低 | REST API |
| 集体备课 | L2 | 0 | 中 | 协作编辑（OT/CRDT） |
| 教案审核 | L1 | 0 | 低 | REST API |
| **小班课授课** | **L2** | **1** | **高** | **WebSocket + 频道机制** |
| **大班课授课** | **L3** | **1** | **高** | **WebSocket + 消息队列** |
| **多班级同时上课** | **L4** | **5-10** | **高** | **微服务 + 负载均衡** |
| 全校同时在线 | L5 | 50-100 | 高 | 微服务 + CDN + 弹性伸缩 |
| 学生课后作业 | L4 | 0 | 中 | REST API + 异步处理 |
| 家校沟通 | L2 | 0 | 中 | 即时消息 |

### 1.1 角色分类体系

#### 按使用场景分类

```
教育系统用户角色
├── 核心用户 (直接使用系统完成主要任务)
│   ├── 备课教师 (UR-001)
│   ├── 授课教师 (UR-002)
│   └── 学生 (UR-005)
├── 辅助用户 (间接使用或提供支持)
│   ├── 教研组长 (UR-003)
│   ├── 学科带头人 (UR-004)
│   └── 家长 (UR-006)
└── 管理用户 (系统管理和配置)
    └── 系统管理员 (UR-007)
```

#### 按能力水平分类

| 能力水平 | 角色特征 | 功能需求 |
|---------|---------|---------|
| **专家用户** | 学科带头人、资深教师 | 高级功能、模板管理、经验分享 |
| **普通用户** | 一线教师 | 标准功能、快速生成、个性化调整 |
| **初级用户** | 新入职教师 | 引导流程、模板选择、AI辅助 |

#### 按组织关系分类

| 组织关系 | 角色特征 | 协作模式 |
|---------|---------|---------|
| **独立用户** | 个人教师 | 独立备课、个人教案库 |
| **协作用户** | 同科组教师 | 资源共享、协作编辑、教案审核 |
| **层级用户** | 教研组长→教师 | 审批流程、督导反馈、统计分析 |

### 1.2 角色详细定义

#### UR-001: 备课教师

| 属性 | 说明 |
|-----|------|
| **角色名称** | 备课教师 |
| **角色类型** | 核心用户 |
| **使用频率** | 每日多次 |
| **权限级别** | 完全权限（对自己创建的内容） |
| **职责描述** | 负责课程设计、教案编写、课件制作、习题设计 |
| **典型用户** | 语文/数学/英语等各学科教师 |
| **工作场景** | 课前备课、个人练课、准备教学资料 |

**核心需求**：
- ⚡ 快速生成教案（输入课程主题→AI生成完整教案）
- 📚 自动搜索课程标准
- 🎯 生成教学目标（知识、技能、过程、情感、素养五维度）
- 📝 设计详细教学过程（导入→新授→练习→小结→作业）
- 🖥️ 生成课件大纲（10-15页标准结构）
- 🔍 搜索教学资源（PPT、视频、习题）
- 💬 接收和响应反馈
- 📦 导出教案和课件

**数据操作**：
- ✅ 创建教案
- ✅ 编辑教案（自己的）
- ✅ 删除教案（自己的）
- ✅ 查看教案（自己的）
- ✅ 导出教案
- ❌ 查看他人教案（需权限）
- ❌ 编辑他人教案（需权限）

#### UR-003: 教研组长

| 属性 | 说明 |
|-----|------|
| **角色名称** | 教研组长 / 备课组长 |
| **角色类型** | 辅助用户 |
| **使用频率** | 每周1-2次 |
| **权限级别** | 审核权限（查看+批注+审核） |
| **职责描述** | 负责审核教案、提供反馈建议、组织集体备课 |
| **典型用户** | 语文组组长、数学组组长、英语组组长 |
| **工作场景** | 集体备课、教案审核、教学研究 |

**核心需求**：
- 👀 查看教师提交的教案
- ✏️ 批注反馈意见
- ✅ 审核通过/不通过
- 📊 查看教研组教案统计
- 📋 组织集体备课
- 🎯 统一教学标准和要求

**数据操作**：
- ✅ 查看教案（本教研组的）
- ✅ 批注教案
- ✅ 审核教案（通过/不通过）
- ✅ 查看教案统计
- ❌ 编辑他人教案（只能批注）
- ❌ 删除他人教案

**审核工作流**：
```
备课教师提交 → 教研组长审核
  ↓            ↓
未通过        通过
  ↓            ↓
修改意见      发布使用
  ↓
备课教师修改
  ↓
再次提交
```

## 3. 教师角色深度分析

### 3.1 教师工作全流程

基于K12教育产品的最佳实践，教师的全链路工作流程如下：

```
┌─────────────────────────────────────────────────────────────┐
│                        教师工作全流程                        │
└─────────────────────────────────────────────────────────────┘

【课前准备阶段】
  1. 集体备课
     → 参与教研组集体备课
     → 备课标、备教材、备教具、备学生、备教法、备板书、备作业、备资源
     → 分工合作，共享资源
     → 系统需求：资源共享、协作编辑、评论批注

  2. 个人备课
     → 根据集体备课的框架进行个性化调整
     → 使用AI生成教案和课件
     → 设计教学目标和教学过程
     → 系统需求：AI生成、模板选择、个性化编辑

  3. 个人练课
     → 按照课表和时间约束进行演练
     → 熟悉教学流程和时间分配
     → 系统需求：教学计时、流程提醒

  4. 集体批课
     → 有经验老师对新老生课程进行点评
     → 提出改进建议
     → 系统需求：在线批注、反馈收集

  5. 备课审核
     → 教研组长审核教案和课件
     → 提出修改意见或通过审核
     → 系统需求：审核工作流、通知系统

  6. 课前准备
     → 准备课件、习题、教具
     → 课前提醒
     → 了解学生基本功
     → 系统需求：课前提醒、学生预习情况查看

【课中授课阶段】
  7. 知识点讲授
     → 复习旧课 → 引入新课 → 新知讲解 → 巩固练习 → 课堂总结 → 布置作业 → 板书书写
     → 使用课件和互动工具
     → 系统需求：课件播放、互动工具、计时提醒

  8. 学情监测
     → 实时关注学生学习进展和纪律
     → 随堂测试
     → 系统需求：实时反馈、随堂测试、学情监测

  9. 疑难解答
     → 及时处理设备或知识问题
     → 系统需求：智能答疑

【课后服务阶段】
  10. 课程文件发放
      → 发送课堂大纲、阶段测试资料
      → 系统需求：文件分享、通知系统

  11. 课后活动组织
      → 组织口语打卡、群内测验等
      → 系统需求：活动管理、打卡功能

  12. 课后答疑
      → 响应家长或学生的疑问
      → 系统需求：智能答疑、在线答疑

  13. 学情跟踪
      → 1v1阶段性测验与点评
      → 掌握学习情况
      → 系统需求：学情分析、错题统计、进步跟踪

  14. 续报沟通
      → 通过群聊或1v1方式推动课程续报
      → 系统需求：家校沟通、数据分析

  15. 情感关怀
      → 对学生生活关怀
      → 增强师生关系
      → 系统需求：学生档案、关怀提醒
```

```
  ↓
```

```
  ↓
整合审核
```

### 7.0 PostgreSQL单库方案说明 ⭐ v1.1 新增

#### 7.0.1 方案概述

AI教师Agent采用**PostgreSQL 16+单库方案**，简化技术栈，降低运维复杂度，同时满足1000+并发用户的需求。

**核心决策原因**：

1. **简化技术栈**：减少Redis、MongoDB等额外组件，降低运维复杂度
2. **功能完备**：PostgreSQL 16+具备JSONB、全文搜索、LISTEN/NOTIFY、事务性队列等功能
3. **性能满足**：对于中小型在线教学场景（1000+并发用户），PostgreSQL性能足够
4. **ACID保证**：保证数据一致性，无需分布式事务
5. **成本效益**：单数据库方案降低基础设施成本（数据库实例-67%、备份策略-67%、监控指标-67%、故障排查-67%）

#### 7.0.2 技术替代方案

| 功能需求 | 原方案（PostgreSQL + Redis + MongoDB） | PostgreSQL单库方案 | 性能对比 |
|---------|-----------------------------------------|------------------|---------|
| 关系数据 | PostgreSQL | PostgreSQL | 一致 |
| 文档数据（日志、配置） | MongoDB JSON | PostgreSQL JSONB + GIN | 简单查询1-3ms（MongoDB <1ms），复杂查询10-30ms（MongoDB 5-10ms）✅ 可接受 |
| 缓存/会话（频道状态） | Redis | PostgreSQL UNLOGGED表 | 读取1-3ms（Redis <1ms），写入3-5ms（Redis <1ms），吞吐量10-20K ops/s（Redis 100K ops/s）✅ 满足1000并发 |
| 消息队列（异步任务） | Redis/RabbitMQ | PostgreSQL SKIP LOCKED | 延迟10-50ms（Redis <10ms）✅ 满足<500ms要求 |
| 实时通信（频道广播） | Redis Pub/Sub | PostgreSQL LISTEN/NOTIFY | 延迟10-50ms（Redis <10ms）✅ 满足<100ms要求 |
| 全文搜索 | Elasticsearch | PostgreSQL tsvector | 满足简单场景 ✅ |

#### 7.0.3 PostgreSQL特性应用

**1. UNLOGGED表（替代Redis缓存）**

```sql
-- UNLOGGED表不写入WAL日志，写入速度快3-5倍
-- 但数据库崩溃时会丢失，适合缓存/会话数据

    channel_id VARCHAR(64) PRIMARY KEY,
    current_page INT,
    active_students INT,
    last_update TIMESTAMP
);

-- 使用pg_prewarm预热缓存

```

**2. JSONB + GIN索引（替代MongoDB）**

```sql
-- JSONB存储文档数据
CREATE TABLE teaching_logs (
    log_id SERIAL PRIMARY KEY,
    channel_id VARCHAR(64),
    log_data JSONB,  -- 存储复杂的日志结构
    created_at TIMESTAMP DEFAULT NOW()
);

-- GIN索引加速JSON查询

-- 高效JSON查询
SELECT * FROM teaching_logs
WHERE log_data @> '{"type": "quiz_answer"}';
```

**3. LISTEN/NOTIFY（替代Redis Pub/Sub）**

```python
# 服务器端发送通知
conn.execute(f"NOTIFY quiz_stats_{channel_id}, '{stats_json}'")

```

**4. SKIP LOCKED（替代Redis队列）**

```sql

BEGIN;
SELECT * FROM job_queue
WHERE status = 'pending'
ORDER BY created_at
LIMIT 1
FOR UPDATE SKIP LOCKED;

UPDATE job_queue SET status = 'processing' WHERE id = ...;
COMMIT;
```

#### 7.3 实时统计机制

**随堂测试实时统计**（PostgreSQL事务 + LISTEN/NOTIFY）：

```python
# 使用PostgreSQL事务保证原子性
def submit_quiz_answer(channel_id, student_id, question_id, answer):
    conn = get_db_connection()
    try:
        with conn.cursor() as cur:
            # 开启事务
            cur.execute("BEGIN")

            # 记录学生答案
            cur.execute("""
                INSERT INTO quiz_answers (channel_id, student_id, question_id, answer, submitted_at)
                VALUES (%s, %s, %s, %s, NOW())
                ON CONFLICT (channel_id, student_id, question_id) DO UPDATE
                SET answer = EXCLUDED.answer, submitted_at = NOW()
            """, (channel_id, student_id, question_id, answer))

            # 原子更新统计
            cur.execute("""
                INSERT INTO quiz_stats (channel_id, submitted_count, correct_count)
                VALUES (%s, 1, %s)
                ON CONFLICT (channel_id) DO UPDATE
                SET
                    submitted_count = quiz_stats.submitted_count + 1,
                    correct_count = quiz_stats.correct_count + %s,
                    updated_at = NOW()
                RETURNING submitted_count, correct_count
            """, (channel_id, 1 if answer == correct_answer else 0,
                  1 if answer == correct_answer else 0))

            submitted_count, correct_count = cur.fetchone()

            # 计算正确率
            correct_rate = (correct_count / submitted_count) * 100 if submitted_count > 0 else 0

            # 提交事务
            conn.commit()

        # 使用LISTEN/NOTIFY推送实时更新
        conn.execute(f"NOTIFY quiz_stats_{channel_id}, '{json.dumps({\"submitted_count\": submitted_count, \"correct_rate\": correct_rate})}'")

        return {
            "submitted_count": submitted_count,
            "correct_rate": correct_rate
        }
    except Exception as e:
        conn.rollback()
        raise e
    finally:
        conn.close()

# 教师端监听实时更新
async def listen_quiz_stats(channel_id):
```
